# デザイン原則（数値付き）

技術登壇・社内勉強会のスライドで守る原則。テーマ `tech-light.css` はこの値を既定として持つので、
Markdown を書く側が意識するのは「量」と「構造」だけでよい。

## 1 枚の構成

```
┌──────────────────────────────────────────────┐
│ # タイトル            … 何の話か（名詞句、30 字以内）      │
│ リード文              … この 1 枚で一番伝えたい一文（60 字以内）│
│                                                          │
│ オブジェクト配置範囲   … リード文の理由・根拠を図解で示す      │
│                        （並列 / 比較 / フロー / 数値 / コード …）│
└──────────────────────────────────────────────┘
```

- **1 スライド 1 メッセージ。** メッセージはリード文に書く。タイトルはその話題の名前
- **リード文は必須ではない。** 図・画面・数値だけで伝わるなら省く。書くなら 1 行（全角 36 字目安）に収める。2 行に折り返すリード文は削るか、枚を分ける
- **補足文（`.note`）は逃げ場にしない。** 出典を 1 行書く場所であって、本文の続きを置く場所ではない。「他に〜もある」「〜も提供」を足したくなったら、要る情報なら 1 枚にし、要らない情報なら話者ノート（HTML コメント）へ回す。**あえて書かない**も選択肢
- **口頭で補う内容は話者ノートに。** スライドに載せない背景・数字・出典は HTML コメントに書く。発表者はそこで話し、聴衆はスライドを読まずに済む
- リード文は「主張」の完全な一文にする（Assertion-Evidence 構造）。「〜について」「〜の概要」は主張ではない
- オブジェクト配置範囲はリード文の**根拠**だけを置く。根拠にならない要素は削る
- 根拠が複数のメッセージを持つなら、スライドを分ける
- ヘッダー・フッター・ページ番号・ロゴ・装飾線・意味のない図形は置かない（テーマが既にそうなっている）
- 箇条書きだけのスライドを続けない。3 枚に 1 枚は図解・コード・数値のいずれかを置く

## タイポグラフィ（1280×720 キャンバス。1pt ≒ 1.33px）

| 要素 | px | pt 換算 | 備考 |
|---|---|---|---|
| 表紙タイトル | 60 | 45 | 2 行まで |
| メッセージ 1 枚（`message`） | 56 | 42 | 2 行まで |
| タイトル `#` | 44 | 33 | 1〜2 行 |
| リード文 | 30 | 22.5 | 強調色・太字。1〜2 行 |
| 本文 | 28 | 21 | |
| カード・図解内の本文 | 24 | 18 | **下限。これより小さい文字を作らない** |
| コード | 24 | 18 | 8 行以内が理想、15 行が上限 |
| 注記・出典・軸ラベル | 20 | 15 | 出典など「読まなくてよい文字」だけに使う |
| 大きな数値 | 96 | 72 | 単位は 36px で添える |

- 書体は 3 種だけ：和文ゴシック（Noto Sans JP → Hiragino Sans）、欧文はその和文フォント内の英数字、等幅（JetBrains Mono → Menlo）
- 1 枚の中で文字サイズは 3 段階まで（タイトル / リード / 本文）。4 段階目が要るなら情報が多すぎる
- 行間：本文 1.6、見出し 1.35、コード 1.5
- 強調は**太字**か強調色。下線・斜体は使わない（`*em*` はテーマが強調色の太字に置き換える）
- 英数字と和文の間は半角スペースを入れる（`invalidate() の呼び出し`、`3 週間`）
- 「。」で終える文と終えない文を 1 枚の中で混ぜない。リード文・カード本文は句点なしで揃える

## 余白・配置

| 項目 | 値 |
|---|---|
| 外周の余白 | 左右 88px、上下 64px（テーマの padding） |
| 要素間の隙間 | 28px（`--gap`）。カード同士・列同士はこれで揃える |
| 並列要素の数 | 2〜4 個。5〜6 個は 2 段組みか縮小、7 個以上は 2 枚に分ける |
| 箇条書き | 最上位 5 項目以内、ネスト 2 段まで、各項目 1 行 |
| 1 枚の文字量 | 本文 220 字以内（コード・タグを除く） |
| 揃え | 左揃えが基本。中央揃えは表紙・章扉・メッセージ 1 枚・DEMO だけ |

- 図解が 1 つだけのスライドは、テーマが残り領域の上下中央に寄せる。上に詰めたいときは図解の後に注記（`.note`）を置く
- 箱の高さは内容に合わせる。下が空くのは問題ない。空きを埋めるために要素を足さない
- **対称のために項目を作らない。** 左 3 つ・右 3 つが気持ちよくても、実在しない打ち手や事例を足してはいけない。2 対 3 のままでよい
- **他者の取り組みに評価語を付けない。** 「地味な」「悲観的」「遅れている」のような形容は、その仕事をしている人が聴衆にいる前提で避ける。事実と条件だけを書く
- 「意味のある空白」と「埋め忘れ」の違いは、視線の流れが止まらないこと。左上→右下に読めれば成立している

## 配色

| 役割 | 色 | 用途 |
|---|---|---|
| 背景 | `#FFFFFF`（白）／`#FAF8F2`（アイボリー） | デッキ全体で 1 つ。frontmatter の `class: ivory` |
| 本文 | `#1F2328` | 真っ黒 `#000` は使わない |
| 補足 | `#57606A` | カード本文・キャプション |
| 注記 | `#8B949E` | 出典・薄い矢印。20px 以上でのみ使う |
| 面 | `#F6F8FA`（アイボリー時 `#F1EEE6`） | カード・コード背景 |
| 罫 | `#D0D7DE` | 枠線 1px |
| 強調色 | `#0E7C66`（teal） | **1 デッキ 1 色。** 面積比で 5% 以内 |
| 強調色の薄面 | `#E3F2EE` | 主役カードの背景・章扉 |

- 強調色は差し替え可（`accent-indigo` / `accent-coral` / `accent-slate` / `accent-plum`）。デッキの主題に合わせて 1 つ選び、途中で変えない
- 主従は「色を増やす」のではなく「強調色の薄面 + 枠線」（主役）と「面 + 枠線なし」（従）で表す。3 段階目は「破線枠」（未確定）
- 赤・黄などの警告色は `.callout.warn` だけ。エラーの話をするときに限る
- コントラスト：本文 `#1F2328` on 白 ≒ 15:1、補足 `#57606A` ≒ 6.7:1、強調文字 `#0B6653` ≒ 6.3:1。WCAG AA（4.5:1）を全て満たす
- 色だけで意味を伝えない。強調色の面には枠線か太字ラベルも付ける

## 生成物に出やすい「AI っぽさ」を避ける

- タイトル下の飾り線、左端の色帯、全幅のヘッダーバー → 置かない
- 全部が同じ角丸カードで並ぶ「SaaS カード地獄」 → 並列は最大 4、他の型（フロー・比較・数値）と交ぜる
- 見出しの 1 語だけ色を変える、ALL CAPS の小見出し、`A · B · C` の中黒区切り、文末の `→`
- 内容が順序を持たないのに `01 / 02 / 03` の番号を付ける（番号は手順・順位・章のときだけ）
- 「効く」「刺さる」など効果を断定する言い回し、「〜の概要」「〜について」で終わる主張なしのタイトル
- 空白を埋めるための装飾アイコン。アイコンは並列要素の識別に使い、1 枚で 3〜4 個まで
- 温かみを出すためだけのクリーム色背景と赤茶の強調色の組み合わせ。ここでは背景は白かアイボリー、強調色は teal 系を既定にしている

## 参考にした原則の出典

- Assertion-Evidence（Michael Alley, Penn State）：主張の一文 + 根拠の図
- Presentation Zen（Garr Reynolds）：シグナル／ノイズ比、余白、1 枚 1 画像
- Death by PowerPoint（David JP Phillips）：1 枚 1 メッセージ、要素 6 個以下
- 伝わるデザイン（高橋佑磨・片山なつ）：ゴシック体、揃え、色は 3 色、4 行以上は左揃え
- Zach Holman / speaking.io：「文字を大きくして、半分に削って、もっと大きくする」
- パワーポイントのデザインパターン大全（CONE inc.）：タイトル → リード文 → オブジェクト配置範囲、39 の図解パターン
