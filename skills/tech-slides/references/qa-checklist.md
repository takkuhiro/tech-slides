# QA チェックリスト

lint（機械）→ 描画して目視（コンタクトシート）→ 直したページだけ拡大確認、の順で行う。
**lint 0 件は「崩れていない」であって「伝わる」ではない。** 目視を省かない。

## 1. 機械チェック

```bash
python3 scripts/lint_slides.py deck.md
```
error が 0 になるまで直す。warn は理由を説明できるなら残してよい（例：Appendix の表）。

## 2. 描画して全ページを見る

```bash
scripts/build.sh deck.md
```
`deck-preview/sheet-NN.png` を順に開く（6 枚 / シート）。次を見る：

### 溢れ・切れ（最優先）
- [ ] 文字が箱や画面の端で切れていない（右端・下端）
- [ ] コードの 1 行が右に溢れていない
- [ ] タイトルが 3 行になっていない。リード文が 3 行になっていない
- [ ] カードの中で見出しが折り返して 3 行になっていない

### 構造
- [ ] 1 枚に主張が 1 つ。リード文を読めば図解を見なくても言いたいことが分かる
- [ ] 図解はリード文の根拠になっている（無関係な要素が無い）
- [ ] 主役（`emph`）は 1 枚に 1 つ。無いか 2 つ以上なら見直す
- [ ] 並列要素が 6 個以下、箇条書きが 5 項目以下
- [ ] 同じ型（cols-3 など）が 3 枚以上続いていない

### 見た目
- [ ] **原寸で 1 枚ずつ見たか**（コンタクトシートだけでは重なり・折り返し・境界は見えない）
- [ ] 重ね合わせた図形（ベン図など）で、重なった領域が別の色として見える。片方が他方を覆い隠していない
- [ ] 2 分割で本文の箇条書きが 1 行ずつ折り返していない（折り返すなら図を小さくするか文を短く）
- [ ] 白背景の画像がスライドの地と溶けていない（枠か面で輪郭がある）
- [ ] 余白が均等（左右の余白、カード間の隙間）
- [ ] 文字サイズが 3 段階以内。20px 未満の文字が無い
- [ ] 強調色が 1 色。面積が広すぎない（章扉以外で背景の 1/4 を超えない）
- [ ] 意味のない装飾（線・帯・アイコン）が無い
- [ ] 画像が粗くない・歪んでいない。スクリーンショットの注目箇所が分かる
- [ ] ターミナル型のコードで文字が読める（暗色背景で沈んでいない）

### 文言
- [ ] 数字・固有名詞・URL が正しい（推測で埋めた値が無い）
- [ ] 表記が揃っている（全角・半角、句点の有無、英数字前後の半角スペース）
- [ ] 「〜について」「〜の概要」のような主張なしタイトルが無い
- [ ] 表紙の日付・イベント名が当日のもの

## 2.5 別の目で見る

`slide-review` スキルを Agent ツールで別エージェントとして起動し、`<slug>.md` と `<slug>-preview/` の PNG を渡す。
作った本人は見たいものを見るので、初見の指摘を必ず 1 度は通す。指摘は「直す」か「理由を付けて残す」に振り分ける。

## 3. 直したページだけ拡大して確認

```bash
pdftoppm -png -r 96 -f 12 -l 12 deck.pdf deck-preview/p
```
修正後は必ず `build.sh` を再実行してから見る（古い PDF を見て「直っていない」と誤認しやすい）。

## 4. 発表前

- [ ] `deck.html` をブラウザで開き、最初から最後まで矢印キーで送って確認
- [ ] 枚数 × 1.5 分が持ち時間の 90% 以内
- [ ] スピーカーノートが要る枚にコメントが入っている（`--pdf-notes` で PDF にも残る）
- [ ] PDF を投稿する場合（Speaker Deck / Docswell）は 16:9、フォント埋め込み済み（`pdffonts deck.pdf` で emb = yes）
